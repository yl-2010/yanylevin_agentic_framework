# Brain schema

Contract for every entity in this brain. Agents follow it exactly. The generator
scripts in `server/brain-*.js` parse these formats, so a file that drifts from
this schema breaks the graph. Single operator: this tree is never shown to guests.

## Layout

```
brain/
  schema.md              this file
  state.json             cursors (agents update, humans rarely)
  identity.md            current standing map (who, now, pointers)
  identity-school.md     compiled student standing
  identity-accounts.md   address and handle list
  identity-logistics.md  homes, phone, network, current trip pointer
  patterns.md            standing inferences about the operator's behavior
  health.md              standing body facts (sleep band, training era, recovery tells)
  threads/<slug>.md      one page per ongoing thread, deleted when resolved
  journal/YYYY-MM-DD.md  day takes (02:30 job writes previous day), kept forever
  people/
    index.md             GENERATED by server/brain-graph.js
    graph.md             GENERATED edge index (all entity kinds)
    skipped.md           ambient names deliberately not carded
    <slug>/              one folder per person, identical allowed file set
  groups/<slug>.md       friend groups, family chat, clubs
  orgs/<slug>.md         school, work, projects
  places/<slug>.md       durable place identity (not the GPS day log)
  education/             GENERATED mirror of ../classes,todos,dates,projects
```

Never hand-edit generated files (`people/index.md`, `people/graph.md`,
everything under `education/`). Regenerate instead:

```
node server/brain-graph.js
node server/brain-education-mirror.js
```

## Frontmatter contract

Every entity file starts with a frontmatter block. Parsing rules are strict so
a small deterministic parser can read them:

- `key: value` on one line. Scalars are written bare (`relationship: closest friend`).
- Arrays and objects are valid JSON on one line (`aliases: ["Alex"]`,
  `school: {"role": "student", "classOf": 2028}`).
- `edges:` is a block list; each item is one JSON object:

```
---
name: Alex Rivera
kind: person
relationship: closest friend
aliases: ["Alex"]
emails: ["alex@example.com"]
phones: ["+15555550100"]
gender: male
school: {"role": "student", "classOf": 2028}
groups: ["friends"]
edges:
  - {"type": "friend_of", "to": "people/sam-lee"}
  - {"type": "group_member", "to": "groups/friends"}
last_touched: 2026-08-19
---
```

Unknown keys are allowed (the parser keeps them), but check this file before
inventing one; if a field is generally useful, add it here first.

## Entity kinds

| Kind | Location | Required fields | Optional fields |
|---|---|---|---|
| person | `people/<slug>/person.md` | name, kind, relationship, gender, aliases, edges, last_touched | emails, phones, school, groups, birthday, location, contacts_raw |

### Gender

Required on every person card. One of: `male`, `female`, `nonbinary`, `unknown`.
Use `unknown` only when you truly cannot tell; the operator can correct in chat.
Agents use this for pronouns. Do not infer gender from a name alone when the
card or sources give a clearer signal.

| Kind | Location | Required fields | Optional fields |
|---|---|---|---|
| group | `groups/<slug>.md` | name, kind, aliases, edges, last_touched | description fields as needed |
| org | `orgs/<slug>.md` | name, kind, aliases, edges, last_touched | urls, location |
| place | `places/<slug>.md` | name, kind, aliases, edges, last_touched | address, coords |
| education-* | `education/**` | generated, do not edit | |

Groups, orgs, and places use the same body contract as a person card: one-line
frontmatter facts, executive summary, Standing, append-only timeline. They are
single files, not folders.

## Edge enum

Edges live in the source entity's frontmatter. Fixed vocabulary; use
`related_to` only when nothing else fits, and consider extending the enum here
instead.

| Type | From -> To | Meaning |
|---|---|---|
| family_of | person -> person | same family, unspecified role |
| parent_of | person -> person | parent -> child |
| friend_of | person -> person | friendship |
| classmate_of | person -> person | school peers |
| teacher_of | person -> person | teacher -> student |
| advisor_of | person -> person | advisor/mentor -> advisee |
| works_with | person -> person | collaboration |
| group_member | person -> group | membership |
| member_of | person -> org | belongs to org |
| attends | person -> org | student at school/program |
| works_on | person -> org | active project work |
| located_at | any -> place | physical association |
| part_of | education-* -> education-* | todo/date belongs to class/project |
| related_to | any -> any | catch-all, avoid |

The operator is not a node. The `relationship` field IS the edge to them, and
`identity.md` is their page in spirit. Never create `people/yan`.

Agent persona is `SOUL.md` at the repo root, never in this tree. `AGENTS.md`
says how the repo operates. This tree is world knowledge.

Store each relationship once, on the more natural source (teacher_of on the
teacher, parent_of on the parent, friendship on either). The graph generator
computes incoming edges, so both directions are queryable.

## Person folder

Same allowed set for everyone. Only `person.md` always exists; the others are
created the first time there is real content. Never create an empty file.

| File | Contents |
|---|---|
| person.md | REQUIRED. Frontmatter, `> ` executive summary, `## Standing` (current facts about this person only), `<!-- timeline -->` then `## Timeline` |
| relationship.md | How the operator knows them, origin arc, assessment. The only home for "how we met." |
| beliefs.md | What they believe, what motivates them, communication style, hobby horses. Not spelling or aliases. |
| threads.md | Open threads with them; resolved items move to the timeline |
| schedule.md | Recurring calendar. School blocks, advisory, sports or club cadence, other repeating commitments. A single date (a game, a concert, a trip) stays on the timeline, a thread, or education dates. |
| notes.md | Typed misc context (recurring text topics, one-off facts that fit nowhere else) |

Standing is current facts about this person. No "how we met" novel (that is relationship.md), no other people's nicknames or deaths (those live on their cards), no agent ACL (that is personal-agent / SOUL.md). Family tree is edges, not a restated sibling list on every relative. Group Standing is who the group is now and the open plan; dated history stays in that group's timeline.

Read discipline: pull the entity card first
(`node server/brain-entity-card.js <slug>`), then Read only the typed file the
task needs. Do not glob a person's folder to "get everything".

## Compiled truth vs timeline

- Everything above `<!-- timeline -->` is compiled truth: rewrite it freely so
  it reads as current fact. Label uncertainty inline (unconfirmed, inferred,
  as of DATE).
- Everything below is an append-only timeline. Never rewrite or delete entries;
  corrections get a new entry. Ascending date order, append at the bottom.
- Entry format: `- YYYY-MM-DD | fact [source]` where source is iMessage, mail,
  chat, calendar, GPS, or similar. One line per fact.

## Slugs and dedup

- Slug = lowercase name, hyphens for spaces (`alex-rivera`). Collisions get
  a disambiguator (`sam-lee-school`). The slug is the identity; never rename
  without updating every edge that points at it.
- Before creating any entity: check `people/index.md`, grep aliases across the
  target directory, check `skipped.md`. A new name variant for a known person
  is an alias to add, not a new card.
- Merging duplicates: keep the more complete card, merge timelines
  chronologically, merge aliases, repoint edges, delete the duplicate, then
  regenerate the graph.

## Memory pages

| Page | Rules |
|---|---|
| identity.md | Current standing map only: who the operator is, school-year pointer, family/circle slugs, project one-liners, now, pointers. Rewrite a standing line. Never append into it. |
| identity-school.md | Compiled student standing (path, current courses, awards). Dated school events go to the matching org timeline, not here. |
| identity-accounts.md | Address and handle list (what each inbox is for). Not OAuth history, sign-in alerts, iCloud-full, or library holds. |
| identity-logistics.md | Homes, phone, network, current-trip pointer to `threads/`. Dated travel stays on the thread. |
| patterns.md | Standing inferences (habits, tendencies). Each line labeled inferred with a confidence note. Social, agent, GPS-clustering tells. Not Apple Health. |
| health.md | Standing body facts: typical sleep, RHR/HRV band, training era, recovery tells that repeat. Rewrite freely. Inferred lines labeled. Not a daily log. |
| threads/<slug>.md | One ongoing thread each (a trip, a purchase, an open question). Small frontmatter (name, kind: thread, edges to involved entities, last_touched), then current state. Delete the page when resolved; the resolution goes to the relevant entity timelines and that night's journal. |
| journal/YYYY-MM-DD.md | Take for that calendar day. The 02:30 job runs under the next morning's dateKey and writes the previous day's file. Written once. The fact-check job may correct tonight's journal before morning. Older journals stay immutable. Kept forever. |

Person-specific facts never live on these pages. They go on the person card,
optionally with a pointer from a thread.

Identity people lines are `Name (role) \`people/slug\``. Role words (mom, closest) are fine.

Do not put other people's emails, phones, spelling notes, nicknames, birthdays, jobs, or home addresses on identity pages. Those belong on the person card.

The operator's own facts still belong on identity pages: grade, timezone, current-trip pointer, mailboxes on identity-accounts.md, homes/phone on identity-logistics.md.

### Identity size

- One fact per bullet. No identity-family bullet longer than ~220 characters.
- `identity.md` stays under ~80 lines / ~1,200 words.
- Each `identity-*.md` sibling stays under ~1,500 words.
- Dated events never go into standing.
- Synthesis rewrites a standing line. It does not append into it.

## Education mirror

`education/` inside the brain is a generated, read-only projection of the
operator's classes, todos, dates, and projects. Source of truth stays in
`../classes`, `../todos`, `../dates`, `../projects`. Regenerate with
`node server/brain-education-mirror.js`.

## Location and health sources

GPS day logs stay in `../location/`. Health day logs stay in `../health/`.
`places/` is durable place identity. `health.md` is standing body facts.
Do not copy a single day's log into either.
